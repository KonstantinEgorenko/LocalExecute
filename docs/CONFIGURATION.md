# Configuration

Semantic YAML is canonical. Historical filenames and keys are interpreted by harness.compatibility.configuration; duplicate normalized keys fail closed. Numeric policy, model tags, routing profiles, environment variable names and serialized keys are not branding substitutions.

The18 legacy/semantic normalized pairs compare equal in this baseline. Their duplicate files have been removed; the canonical semantic documents retain their values. Model-only reserve0 is intentional; a separate experiment threshold must not be misrepresented as a production guarantee.
